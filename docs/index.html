Decay

Notes with a life. They sit at temperature before you can act on them, they grow with attention, and when they are neglected they compost into a soil you can still search.

Open Decay
Status Built and working offline: notes that fire for a set number of days (locked, but open to additions), cool onto the shelf, then live or fade by attention; vitality from recency, reopens and links; compost into a searchable soil; re-seeding with links intact; a spore that resurfaces a buried note; export of the whole colony.
Release: Windows EXE, Android APK and Linux binary, built from this source in CI — app-latest.
Not built: inferred links. The Mycelium prompt asks for on-device embeddings to guess connections; there is no embedding model in this estate, so every link is one you made, and the app says so.

What it does

  • Write a note, or an idea with a firing time — it is locked until it cools, and it can accrue additions meanwhile.
  • Vitality from three things only: how recently you touched it, how often you reopened it, how many links it has.
  • Neglect past the rot threshold moves a note out of the living view and into the soil — nothing is deleted.
  • Search spans the living notes and the soil, so a word only a composted note holds is still findable.
  • Re-seed a composted note and it comes back with its links intact. Or send a spore and let the soil choose.

What it will not do

  • Infer your links. No embeddings, no similarity, no model — a link is a decision you made.
  • Delete anything. The soil keeps what the living view let go of.
  • Run the rot on a store it could not write. If the save fails, nothing decays either — otherwise it would compost notes it never saved.
  • Treat an unreadable colony as an empty one. That would decay the difference away; it is reported and offered for export instead.
  • Use a model, a key or a network. No fetch, no endpoint; CSP connect-src 'none'.

When things go wrong

CaseWhat happens
Bad inputA note with no body is refused. A firing time of zero — an idea that never comes due — is refused with the rule named, and a firing time that would cool in the past is refused with the date shown.
No networkNothing changes. The colony is on the device.
Storage full or unavailableThe note is not written and the app says so; the rot does not run on a store it could not write.
Corrupt saved stateReported and offered for export. The app never treats an unreadable store as an empty one.

How to run it

  • Here: play/index.html, or install it from your browser's menu.
  • Offline file: open docs/play/index.html straight from disk.
  • Tests: node tests/self-tests.js — the spec's countable “done means” is asserted there, including the five reopens and the soil search.
